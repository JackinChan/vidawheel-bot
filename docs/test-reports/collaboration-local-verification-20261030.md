## 实现范围

- 飞书官方 SDK 的群消息及 drive.notice.comment_add_v1 注册，长连接与带验证的 HTTP 回调二选一。
- 评论通知按应用、租户、接收机器人、文件对象白名单过滤，同一评论串/群话题关联原任务。
- 原始事件去重，验证凭据不入库；新增事件递增版本，分析期间新增信息会触发后续分析。
- PostgreSQL 租约、原子领取、超时回收、三次失败上限、退避、分析历史及文本/评论证据快照。
- MCP 等待领取及失败记录；worker 自动领取、心跳续租、只读 Codex CLI 调用和提交结果。
- docx 原文、block、引用、完整分页评论；来源身份下载的图片作为 CLI 图像输入。非图像附件保留 block 元数据。

## 验证层次

1. PostgreSQL 集成与文档 MockTransport 测试共七项，覆盖去重、授权隔离、并发、过期令牌、串关联、版本补分析、重试上限、证据快照、回复分页和图像下载；使用可清空测试库。
2. Docker MCP + HTTP callback + 模拟飞书 API + 合成 worker：真实 HTTP 提交带签名事件，校验 challenge、拒绝伪造签名、重复事件不新增、同串追加、读取两页回复和引用、自动领取及结果回写数据库。合成结果明确标注 SYNTHETIC TEST ONLY，不冒充模型分析。
3. 本机真实 Codex CLI 调用已收到模型最终响应，但该次只读文件命令被本机执行策略阻止。因此仅证明 CLI/模型进程通信，不能视为仓库代码分析通过；未放宽执行策略或绕过审批。

容器内独立验证 `codex --version` 返回 0.166.0；`codex login status` 返回未登录，符合未复制宿主凭据的预期。最终合成 worker 验收后，数据库任务为 completed，分析记录关联任务版本 2 与来源文档版本 7。

## 尚需外部条件

- 测试群、真实应用事件配置和文档权限尚未由用户提供；不发送真实飞书消息，不声明真实投递验收通过。
